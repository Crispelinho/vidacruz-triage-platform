## Method and verdict criteria

1. **Literal-source test (a):** for every XW row I searched for the asserted statement itself, not for a semantically similar idea. A row is "literal" only where the cited wording is present in an authorized document at the stated version and section. Line numbers are 1-based as read from the files.
2. **Classification test (b):** `CROSS-WORKSTREAM DEPENDENCY` is confirmed only for an evidenced cross-flow linkage; `POTENTIAL CONTRADICTION` is confirmed only for conflicting or unsupported statements needing owner resolution. Where a claim has no literal source, the label is retained as **unconfirmed** and is not treated as evidence of a contradiction.
3. **Verdict test (c) — proposals only:**
   - `CLOSE PROPOSED` — literal evidence is complete and the mismatch is a self-contained documentary error whose correction needs owner-approved **editorial** work, not a normative decision.
   - `KEEP OPEN` — the claim is unsourced, or the authoritative statement is absent from the authorized corpus; a source must be supplied before any closure can be reasoned about.
   - `ESCALATE TO DEVELOPER` — resolution requires an explicit Developer/User act (ADR status, gate, decision node, ID namespace or permission to work under an open variable).
4. **Non-inference rule (d):** every row carries an explicit no-closure statement. Nothing below was reclassified by inference; in particular no `B4`/`B5` mapping, no addendum-`D2` → V3-`D2` mapping, no new causal chain and no selected dependency chain was invented.
5. **Document versions:** ADD-V2 = V2, 2026-11-25, "independent document — proposal pending user review" (header lines 4–8). MATRIZ = independent revision, 2026-11-25, "proposal pending user review" (lines 3–5). ADR-02/ADR-03/ADR-08 = **Proposed. Not accepted.** (line 3 of each).
